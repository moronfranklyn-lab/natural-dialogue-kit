# 产品需求文档

| 字段 | 内容 |
|---|---|
| 产品 | Natural Dialogue Kit |
| 文档版本 | 0.1.0 |
| 日期 | 2026-10-25 |
| 定位 | 可复用的对话设计与评审工具包 |
| 交付形态 | 文档、JSON 配置、离线脚本、Agent Skill |
| 当前边界 | 不提供聊天服务、模型托管或记忆引擎 |

## 1. 背景与问题

陪伴聊天与任务执行常共用模型入口。为了减少客服腔，产品可能加上字数、分段、问号和口头禅规则；这些规则又会制造固定句式。另一种问题是把“有性格”实现为每轮反击，把“能继续聊”实现为每轮提问。

原产品迭代显示这些失配值得处理，但现有证据来自有限产品情境和主体验者，不足以建立普遍因果结论。

## 2. 用户与使用场景

| 用户 | 任务 | 所需交付 |
|---|---|---|
| AI 产品经理 | 把“像客服”反馈变成可讨论的问题 | 场景、反例、需求与验收表 |
| 提示词设计者 | 调整角色，避免换一种模板 | 可版本化配置与多轮评审 |
| Agent 开发者 | 增加人格并保留业务可靠性 | 运行时边界、数据契约、回归清单 |
| 开源使用者 | 复用方法而非复制整个应用 | 独立 Skill、脚本与示例 |

典型场景：用户分享一件已经解决的事；只发问号；连续沿用一个玩笑；低落时不想接受建议；闲聊中突然要求教程或操作。

## 3. 目标与非目标

目标：让语气适配当下、允许表达长短变化、减少没有必要的服务性续问；让角色变化可追踪；让任务能力退化能被单独发现。

本期不承诺：提高留存或依恋、通过图灵测试、所有回答简短、模仿某个真人、自动优化人格、建立永久用户画像。

## 5. 体验要求

分享、玩笑不自动变为求助。可以只反应一句，也可以沿着具体细节产生看法。遇到明确任务、事实疑问或风险，不用“人设”掩盖能力不足。情绪和偏好是表达倾向，不能使工具回执失真。

气泡按语义呈现，不按字数切碎；完整正文保持唯一来源。长教程可以用步骤，不能套用闲聊禁列表规则。

## 6. 成功与失败判定

本项目不预设自然度总分和上线数值阈值。使用者应预先确定目标用户、样本、模型和对照版本，并记录人工偏好及原因。

可观察结果：错误解读分享、无必要续问、固定口头禅/反击、角色不一致、虚构经历、业务字段损坏。量化统计只能辅助定位，不能单独认定“像人”。

业务契约应按具体应用要求通过；自然度偏好与契约失败分开报告，不能用聊天好感抵消错误操作。

## 7. 发布策略与风险

先本地渲染与离线检查，再真实模型多轮比较，再业务回归。应用发布保留旧配置和回退入口。没有目标应用的验证，不宣称即插即用或生产已就绪。

主要风险：示例被逐字模仿；语气在长历史中漂移；轻松表达误用于严肃请求；人格影响工具授权；手工评审偏差。缓解方式见评测与架构文档。

## 8. 后续规划

- 当前：文档和工具包公开，收集带上下文的失败案例。
- 下一阶段候选：增加跨模型、多人盲评；补充各应用的业务适配示例。
- 另行验证：记忆相关性、误记、纠错与删除；不预选图数据库或向量架构。

以上为方向，不是交付日期或已承诺功能。
