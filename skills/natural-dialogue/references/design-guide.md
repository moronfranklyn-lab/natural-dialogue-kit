# 配置与评审指南

## 最小配置

使用 JSON 或现有应用格式即可，不强制增加新依赖。可以包含：

```json
{
  "id": "your-persona.v1",
  "identity": "助手是谁，以及与用户如何相处",
  "relationship": "轻松熟悉，也能认真回应",
  "voice": ["表达随语境变化，不为延长对话而追问"],
  "boundaries": ["角色玩笑不冒充事实、用户记忆或已执行操作"],
  "examples": [{"user": "让我安静会儿", "assistant": ["好，我不吵"]}]
}
```

这段用于说明结构，不是已验证人格。不要据此给所有角色统一性格。

身份定义少量有意义的倾向。示例应来自不同情境，包含短反应、具体联想、正常问答、安静收尾和认真解释。不要每条示例都带同一种尾巴，或把示例变成逐字标准答案。

## 常见失配

| 表现 | 先检查 |
|---|---|
| 所有回答同样短、同样几条 | 长度和分条配额、同构示例 |
| 每轮反击或重复语气词 | 人格是否只有一个固定触发动作 |
| 分享后必问“怎么样/要不要帮” | 是否以延长对话为隐含目标 |
| 有礼貌但空洞 | 是否忽略当下具体细节，只剩附和 |
| 教程太碎、卡片缺字段 | 聊天限制是否泄漏到业务协议 |
| 文件改了但体验不变 | 实际主链、版本选择、缓存与部署 |

## 验证

固定提示与模型参数，对比改动前后。使用真实生成输出续接多轮；模拟用户的内容标为合成，不声称真实用户愿意聊下去。保留失败、重试与完整样本。

人工评审看是否接住话意、角色是否连贯、追问是否必要，不用问号比例单独判合格。格式和业务错误另行检查。观察多轮口头禅漂移、旧历史影响以及用户纠正。

有工具的应用还需覆盖：闲聊转教程、推荐卡、事实来源、成功/失败回执、明确写入请求与无授权写入。没有工具的聊天样例不能证明这些场景通过。

## 记忆

分清说话对象、来源、时间、否定、更正与玩笑。朋友偏好不等于用户偏好，今日情绪不等于长期特质；模型标记“明确要求”不等于有用户授权证据。删除还要防止旧摘要重新提取。没有接入证据时不宣称长期记忆已生效。
